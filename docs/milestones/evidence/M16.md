# M16：决策轨迹独立复核

2026-11-19，分支 `claude/project-architecture-review-f9de4i`。交付复核工程与保守筛选闭环；真实 KEEP 准入尚未开放。

## 两阶段与真实来源

`DecisionReviewFactory` 组装 `DecisionSourceFactory`、`ReviewerAdapterFactory`、`AttributionPolicyFactory`、独立存储及 `DecisionReviewPort`。复核器没有执行工具、修改在线路由或发布模型的能力。

来源不是用户提交的一段“成功故事”。服务通过公共 Agent、Experience、Genome、Assess 和 Delegation Port 取得拥有者的实际运行，核对原 `judgment.started` 请求、`completed` 结果、请求 digest、原始 Agent checkpoint、问题/稳定选项与答案。`state_cutoff` 是 Agent 的版本号，不能当作全局事件 cursor。

- A 阶段：只给原始 state、该问题/选项、原答案及决策前证据。没有最终状态、后续费用、验收、用户纠正或“是否采用”。
- A 的输入摘要、输出、实际模型、指纹、派发及用量独立保存后才构建 B；两阶段使用不同、可重放的固定 request id。
- B 阶段：原始问题、冻结 A、后续真实模型/工具/反馈/命令摘要、独立验收、是否采用、目标变化和阻塞因素。完整轨迹 manifest 参与来源 digest；选择固定事件类别减少重复 checkpoint，不把未提供的事实编成反事实。
- 单阶段最多 512 输出 tokens，默认输入 14,000 bytes、预估费用 20,000 microUSD；默认单作业，每个决策/问题最多三个复核请求。大于窗口、裁剪或链路不完整只会降低资格。远程要求用户明确 `public=true` 且原始判断属于 public；local-only 仍由固定网络策略阻止外发。
- 模型输出为严格 JSON。非 unknown 结论必须引用允许集合内的真实证据 id；无引用、假引用、同 actor 模型/指纹、自评分、协议错误都不能当作有效复核。

目前 Laya 仍为 advisory、`adopted=false`。实际采用必须有匹配的 adoption receipt、执行器及被采用的问题；fan-out 的其他答案不能分享执行器选择的信用。当前执行器还没有提供可验证的决策因果/效率对照收据，服务明确标记缺证，不把 actor 成功或模型声称的 controlled replay 作为替代。

多 Agent 子运行通过 Delegation 公共 DAG 关联到父任务的实际版本与子依赖、运行 id，标记 interaction group。联合效果无法分离时单条决策 HOLD。正式输入、银行/验收、晚到反馈、模型/价格配置、目标或运行版本变化会使旧标签失效；重评仍从原始决策前快照构建 A。

## KEEP / DROP / HOLD

| 观察 | 处理 |
| --- | --- |
| 未采用/无效/影子答案 | HOLD，不能继承 actor 成功 |
| 当时合理，但后续仅环境故障 | HOLD，不机械归罪于判断 |
| 当时不合理，有验证的有害因果链，即使后来补救成功 | 满足独立证据/校准后 DROP |
| 合理、实际采用、当前独立验收成功、有验证贡献和效率证据、无分歧且 reviewer 已校准 | 才允许 KEEP |
| 只有相关性、目标变更、联合归因、未知模型或工具副作用、无效率对照 | HOLD |
| 用户提供有效引用的人工 DROP/HOLD 修订 | 排除正向训练；人工 KEEP 不绕过证据与校准 |

`proposed_verdict` 记录原始建议，`verdict` 和 `positive_training_eligible` 读取时重新验证。DROP 不改成 DPO 负样本，不物理删除原始审计。人工纠正以新版本保留原判断；M17 只读取当下仍合格的 KEEP，并须再做数据资格审查。导出输入严格为原 state + 原问题/选项，target 为原答案；后续轨迹只用于筛选，不进入当时的训练输入。

## 独立人工 meta 门禁

独立人工标注需明确确认、准确版本、真实引用及 family/origin_group。原始人工解释只在私有库，不写到模型请求或主轨迹。被用于 reviewer meta 的输入永久保护，端口提供 run id 和规范化输入 SHA 给后续数据模块排除；标签修订不解除保护。

门槛固定在配置中：至少 100 个独立家族、KEEP/DROP/HOLD 各至少 30 个、覆盖≥0.9、kappa≥0.6、预测 KEEP 污染率的 95% Wilson 上界≤1%。零污染也约需 381 个独立预测 KEEP，少量完美例子不能打开门禁。同 family、origin 和规范化输入连通去重，相关标签冲突降低资格。版本、模型指纹、部署声明/价格、原 teacher、问题与选项 schema、数据域和状态长度/语言桶绑定作用域，不能沿用其他版本/分组校准。

同一 subject 的重复标注不增加样本量；纠正需要新 review 版本并保留原 family/origin。过期或被人工修订的旧校准记录失效。Fixture/mock 来源不进入真实校准。当前没有真实人工 meta，门禁关闭，正样本导出为空。纯统计测试使用的合成标签仅验证公式，不能证明筛选器可靠。

## 持久化、API 与页面

私有 `decision_review.directory/decision_review.sqlite3`，schema 1，WAL/FULL、0700/0600、进程独占锁、不可变文档版本/CAS/命令回执。主事件日志只写 digest/版本/范围等元数据。独立 reviewer 网关在 `reviewer-journal` 保存原始请求与结果，不与执行模型 journal 混用。模块只读公共证据 Port；teacher/actor 不能导入其筛选实现。

第一阶段提交后响应丢失，重试读回既有 A，只继续 B。未知派发费用保持 null，失败保留已知消费；已 blocked 的同一请求不自动再次收费。来源变化或进程中断不能通过另建“成功”记录抹除历史。

API 位于 `/api/v1/decision-review/`：`status`、`jobs`、`reviews`、`reviews/{id}/revisions`、`meta`、`calibrations`、`eligible`。所有操作绑定当前拥有者；body 不能伪造 role/owner。页面 `?view=decision_review`（侧栏“决策复核”）包含来源选择、冻结命令、原问题/版本、A/B 分栏、影响链、费用/未知值、三态及排除原因、人工修订历史与校准门禁。默认公开外发和独立人工确认都为 false。
