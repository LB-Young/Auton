# M21 后台运行与恢复工程证据

## 交付范围

实现 SchedulerFactory、JobQueueFactory、TelemetryFactory、RetentionPolicyFactory，以及公共 Port、配置/生命周期、独立私有状态、OpenAPI/前端契约和 `?view=operations` 页面。M21 没有导入发布/审批模块，不取得自动批准、上线或学生接手权。

训练使用 M18/M19 通用部署流程，不读取当前开发电脑的硬件来选模型、下载或训练。实际 CPU/GPU 训练效果、部署隔离和长周期收益仍需最终部署环境验收。

## 检查结果

- `make check` 最终通过：294 项后端测试；244 个文件 strict mypy；Ruff/格式；39 条模块边界；OpenAPI/生成 TypeScript 一致性；前端 lint/build。
- 调度专项 19 项通过，均为明确的控制协议 fixture，不当作真实模型质量或真实 GPU 抢占证据。
- 最终全量浏览器 24 项通过，78.71s。覆盖后台默认禁用、创建默认未授权计划、暂停身份、备份、刷新、移动端无横向溢出，并验证新增菜单后的主导航滚动。
- 最终接口下定向复验小屏导航和后台页面 2 项通过；界面检查后补齐共享表单样式，最终发布/后台/导航 3 项复验通过（6.07s），截图已更新。
- 未声称 GitHub CI、真实模型训练、上线或周/月尺度线上收益通过。

新增公共资产模块并发回归：并发首次读取同一快照和同一 goal，修复前可稳定触发版本竞态；修复后在窄锁内确认唯一快照/分组，来源 guard 保持在锁外，避免递归校验死锁。资产、发布、上下文、调度相关 57 项回归通过。

专项故障包括：

1. 同一任务请求重复提交、调度重启、真实上游请求 ID 固定；已产生效果但回执丢失后不创建第二个逻辑操作。
2. 同时领取、租约过期、旧 token/版本拒绝写入、失败指数退避上限。
3. 前台阻止后台新分派、UTC 窗口、已有后台训练停止及显式 checkpoint 恢复；暂停只停止该身份所属的受管训练。
4. 重命名计划或重复数据不满足新训练数据门槛；默认授权 false，付费任务禁止周期重复。
5. 未知 review 成本保留完整预算；相同告警不重复发布、恢复产生新状态版本。
6. 备份损坏拒绝、非空恢复目标拒绝、默认暂停、保留上游稳定 ID，以及旧备份恢复时避开仍存的审计版本。
7. 有界队列积压/拒绝、模拟 40 天的采样保留、精确身份/项目清理；模拟时钟不当作真实 40 天运行结论。
8. 观察专用命名空间只接受监控/监控保留，不能调用模型/训练/改源权利；自动循环仅执行已明确启用的计划。

## 主要约束与运维

- 默认 enabled=false。用户精确范围、原始数据许可、训练计划/数据/镜像资格仍逐次校验，循环不会扩展未来 run 的权限。
- 快回路监控/撤权，中回路 review/数据，慢回路训练，均有资源窗口、预算、限额、租约和明确状态。前台优先使用全局聚合信号；目标环境还需配置硬资源预留与隔离。
- 新监督数据键按 kind+规范化输入/目标识别，至少 20 个新样本才准入自动训练；运行漂移只告警，不能替代数据许可和训练/发布门槛。
- 通过率/漂移为描述性运行指标，没有因果收益资格。runtime/test 分别统计，未知用量不计作零成本。
- 告警只在本地控制面随状态变化记录；主对话不刷后台日志，不对外发消息。
- 物理 retention 仅处理监控采样；精确数据撤权使用独立 withdraw 操作。原始 trajectory、训练产物和审计不被顺带删除。
- 调度状态备份不是全项目备份；跨机恢复应先协调恢复上游业务库/身份，恢复调度默认 paused。旧 worker、未知副作用、持续资源失联保持 attention，不能伪称已回滚成功。
