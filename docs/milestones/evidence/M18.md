# M18：通用执行模型训练流程

2026-11-19，分支 `claude/project-architecture-review-f9de4i`。

按用户最新要求，本里程碑交付**适用于项目目标部署环境的通用训练流程**，不根据当前开发电脑选择硬件、下载基础模型或执行训练。流程工程可测试；真实模型效果与部署质量仍待目标环境验证，不宣称已经改善模型。

## 工厂与流程

`ExecutorTrainingFactory` 组装 `TrainingBackendFactory`、`TrainingJobFactory`、获准数据读取及版本文档存储，对外只暴露 `ExecutorTrainingPort`。基础模型、实际 tokenizer/template、后端镜像、设备与资源限额来自部署配置，模型网关和在线 Agent 无训练权限。核心服务环境不安装 Torch/PEFT 训练依赖。

1. **计划**：读取 M17 可导出的训练/验证 artifact，复核权限、拥有者、项目、Executor 类型、来源与固定 manifest；validation/replay/anchor 不能用 train split 代替，各池来源组互斥。
2. **基础模型**：核对部署方登记的完整模型 revision、许可依据、每个挂载文件 SHA256 和实际模板 hash。拒绝符号链接、未登记文件、远端 Python 代码与 pickle 权重。元数据未变化时重用已经计算的校验，内容/ctime/mtime/inode/文件清单变化后重新核验。
3. **准入**：正式训练至少需要 20 个 train、10 个 validation、10 个 replay、10 个 anchor 独立来源组。这些是工程下限，不是统计质量保证。工程探针最多三步、始终不可作为发布依据。缺后端、模型、数据或授权时计划阻塞，不静默用 mock。
4. **作业**：固定计划摘要、seed、超参数、数据、镜像；手动启动、幂等请求、全局并发上限、版本化控制。队列/派发/未知 worker 身份可追溯；终态作业不自动重跑。没有确认的 worker 不能假设未运行。
5. **训练**：参考 worker 用 Transformers/PEFT 的 LoRA；先测基线，再训练并复测。按实际 tokenizer offset 映射监督目标 assistant span，用户、system、工具响应不参与 loss；目标边界不兼容、token 跨边界、工具对不完整或超长时拒绝，而非截断。
6. **恢复**：每个提交的 checkpoint 保存 adapter、AdamW 优化器及 CPU/CUDA 随机状态，全部用 safetensors、固定 plan digest 和逐文件 hash 绑定。恢复校验运行设备类别、CUDA 设备数与实际依赖版本。取消后要确认旧 worker 停止，手动恢复仍遵守原总步数预算；不同尝试写入不同目录。
7. **候选**：结果绑定同一 plan 与完整 checkpoint，保存基线/训练后各池 loss、工具协议和精确动作匹配、实际设备、依赖版本、时间与谱系。只能登记 `offline_candidate`，`quality_release_eligible=false`；没有修改在线执行或 Judgment 配置的路径。

标签/域近重复检测沿用 M17 的明确限制。此次另外修复了来源分组：`EvalReport.groups` 是语言、长度、风险、领域等校准桶，operational 的 `family=file/research` 也不是任务家族，不再据此合并来源。显式 train/development case 的真实 family/origin 通过窄 Port 获取并锁定。

## 离线 worker 部署

示例在 `config/training.example.toml`、`containers/training-worker/`。默认后端关闭。部署方先构建并审查镜像，将**实际 image digest** 配入配置；镜像缺失时不会自动 pull。Dockerfile 的基础镜像参数没有隐式默认值，部署方应使用固定 digest。

参考 Docker 后端：网络关闭、只读根文件系统、普通 UID、capabilities 全部丢弃、禁止提权，限定内存/CPU/进程数，单作业输入与基础模型只读挂载，仅本次输出目录可写。没有 provider 密钥、生产工具目录、所有历史数据或 Docker socket 挂载。控制进程不把宿主环境变量传给 worker。worker 有 wall alarm、单文件大小限制；控制器轮询总输出字节与来源变化并停止 worker。bind mount 不具备本实现未提供的硬磁盘配额。

依赖约束文件是构建配方，不声称跨平台构建出同一镜像；真正运行由审查后的 digest 固定。参考 worker 首期按 CPU/CUDA 部署、float32 执行测量，支持配置 tagged JSON 或直接 JSON 工具输出格式。未完成实际量化部署评测时明确记 `quantized_deployment_evaluated=false`。其他训练系统可实现同一 backend port，不能自行绕过数据与发布门禁。

部署步骤：

1. 在目标部署环境构建训练镜像，记录真实 digest 与依赖解析结果；不要给运行中的训练容器网络或生产凭据。
2. 准备获准基础模型的 safetensors、tokenizer 与完整校验清单，配置模型 revision、许可和实际模板 hash。
3. 配置后端、设备选择及预算，使用 M17 的获准 artifact 创建计划。
4. 检查计划 blockers；ready 后手动启动，查看基线、进度、checkpoint 和失败原因。
5. 在相同固定环境恢复/复测，另行进行真实部署精度、受保护终验和 M20 发布审核。

## API 与页面

`/api/v1/training/{status,plans,jobs,bundles}`；作业控制是 `jobs/{id}/commands`。原有数据、模型与发布接口保持分离。训练库独立目录，WAL/FULL、lease、不可变版本和幂等 receipt；重启不会自动恢复一个已中断的昂贵作业。仍在运行的已登记 worker 可被监控，丢失的 worker 身份不会自动重新派发。

`?view=training` 显示部署配置状态、计划/资源/数据谱系、阻塞原因、手动启动、checkpoint、取消/恢复与候选指标。默认未配置可见，不触发模型下载或本机训练。

## 测试与实际限制

- 9 项训练专项测试：正式计划的数据门槛、基础模型变更、幂等作业、候选不可发布、授权撤回中止、取消/恢复、checkpoint 篡改、OOM、磁盘不足、重启不重复训练、容器参数及 token mask/完整工具对/拒绝截断。
- 测试 worker 是明确的控制协议故障替身；其 checkpoint 字节不是真实权重，产物标 `source=test`。测试不宣称数值训练、真实 GPU 隔离或模型改善。
- 数据模块另加校准桶不能充当来源家族的回归测试。
- 浏览器全量 21 项通过（77.81s），覆盖后端未配置、计划默认非探针、阻塞时禁用启动、刷新与 390px 移动端；未在浏览器启动训练。
- 最终 `make check` 全部通过：258 项后端测试、209 个文件 mypy strict、33 个 Python 导入边界，以及格式、前端边界、契约漂移、秘密扫描与前端 lint/build。部署配置示例也通过类型化配置校验。

**待目标部署环境验收**：真实基础模型的 tokenizer/template 兼容、镜像隔离、完整梯度训练与数值恢复、受限域改善、通用/旧能力回归、真实量化部署与总资源成本。用户要求当前只实现通用训练流程，所以这些结果保持未验证，不在当前机器补做训练、不伪造通过。所有候选的发布资格继续关闭。
