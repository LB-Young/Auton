# M02：核心内核与事件持久化验收

日期：2026-11-17。M02 独立实现、验收、提交；后续里程碑不得混入本次提交。

## 交付

KernelFactory、ClockFactory、IdentifierFactory、EventLogFactory 通过公开 Port 组装。Event 包含版本、UTC/带时区时间、source，以及 project/session/goal/task/run/attempt/operation 与目标修订关联。批量 append 是事件事务边界，不宣称与外部系统副作用原子提交。

SQLite 使用 APSW 锁定的内嵌 SQLite 3.54.1，不依赖宿主 Python 的旧 SQLite。启动验证文件、应用标识、schema、完整性与 WAL/FULL；新数据库权限为 0600。拒绝不支持的版本、损坏库和无关数据库，不自动替换/清空文件。

`event_log` 使用自增 cursor、唯一 event_id、canonical JSON 和 SHA-256 digest。相同 ID/相同内容返回原 cursor；同 ID/不同内容拒绝，整批回滚。确认提交才返回 committed；提交确认丢失保留 unknown，调用方按 event_id lookup 对账，不假称失败或重发新 ID。

## 存储位置与兼容规则

- 默认 `.auton_local/kernel/events.sqlite3`，相关 `-wal`/`-shm` 属同一数据库；不要运行中只复制主文件当备份。
- `KernelConfig.data_directory` 可配置。原始 Event payload 在日志内；索引/投影与 artifact 实体由后续模块独立管理，当前不伪建目录或提供任意路径读写 API。
- schema v1 为 cursor/event_id/document；v2 添加 digest 并在单事务中回填。迁移失败回滚 schema、版本和数据；未来版本拒绝降级打开。
- 事件 schema 当前只接受 1，未知事件版本拒绝读取。游标是位置，不要求连续整数；过滤在 limit 之前生效。
- Port 只有追加、查询和健康信息，没有任意 SQL/删除接口。日志是明文，当前不承诺加密；保留/删除与权重撤回治理按后续里程碑实施，禁止自行推断 TTL 清空日志。
- MemoryEventLog 仅允许 test profile，明确 durable=false。普通 Demo 的事件内核为 SQLite，但聊天数据依旧只存在内存；没有提前实现 M10 会话恢复。

## 复现

```bash
make check
AUTON_BROWSER_CHANNEL=chrome make e2e
```

`make e2e` 使用独立临时端口、配置与数据库，退出后只关闭自己创建的进程；不停止默认端口已有服务，也不把旧服务的响应当本次验收。设置页同时展示事件存储和 Demo 会话存储。

## 验收覆盖

- 同一合同下 Memory/SQLite 替换、幂等、冲突整批回滚、调用方数据修改不改已存事实。
- 关闭重开、WAL/FULL、scope 过滤与稳定游标、游标空洞。
- v1→v2 迁移和故意失败后的原库保持；损坏/未来版本/无关数据库拒绝且文件未被替换。
- 多连接并发写、真实写锁超时、实际 SQLite 页限额导致的 SQLITE_FULL。
- COMMIT 前故障为 not_committed；COMMIT 后确认丢失为 unknown，可查询并幂等重试。
- 子进程硬退出：已提交记录恢复，未提交事务不存在。
- 原有 API、来源检查、界面流式/停止/产物、手机布局、主题及输入法/草稿流程无回归。

本地完整检查：34 个非浏览器测试通过；4 个浏览器流程通过；格式、严格类型、依赖边界、契约漂移、前端 lint/build 通过。远端 CI 与本地验收分开记录。
