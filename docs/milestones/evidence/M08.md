# M08：上下文装配、检索与压缩验收

日期：2026-11-18。前置 M07 已独立验收并推送 `9c03c72`。

## 交付范围

新增 ContextEngineFactory、TokenCounterFactory、RetrieverFactory、RerankerFactory、CompressorFactory，显式 Port、配置、依赖和生命周期。Context 通过公开 Port 读取 M07 资产、M06 操作 receipt、M04 模型目录和 M03 策略，使用 M02 事件日志保存快照。Python 实现后端、下载脚本和验收脚本；浏览器使用现有 React/TypeScript 工厂与 API transport。

本次为确定性词项/中文 bigram 检索、固定重排和完整轮次移除。没有启用 Jev/Laya 自动重排，不改变 M05 advisory 门槛，不运行模型生成历史摘要，不覆盖原始历史或持久 checkpoint。

## 装配与信任域

- 唯一 system 消息来自固定宿主代码，包含权限与未知操作对账约束。调用者历史不允许 system 角色。
- 任务状态单独封装目标、必留边界、未决操作、目标修订与状态截止点。声明中的操作必须查到同主体的真实 M06 receipt；成功/失败/未知声明与账本不符时拒绝，不能编造“已成功”。
- Receipt 锚点保留操作 ID、请求摘要、实际 outcome、错误码、证据、artifact 等，正文 output 不重复注入；完整原 receipt 继续存在于 M06。装配前后及快照再次读取都核对 receipt 摘要，操作结果变化要求重建。
- 项目说明与检索证据都作为 user 数据且标明 untrusted，不能升级为 system 或授予工具权限。来源标注是数据边界，不能保证模型不会误信内容；实际执行仍依靠 M03/M06 权限控制。
- 只从同主体/项目的正式 M07 snapshot 检索。旧资产快照读取继续检查当前撤回、过期和父来源状态。跨项目、跨主体或不再允许的来源不能靠旧 context ID 重用。

## 检索与压缩

按配置字符块切分资产，英文词项/中文 bigram 与任务目标计算集合交并比分数，只返回有词项重合的块；固定顺序重排。内容 SHA256 去重时合并全部来源及各自字符区间，不把不同文件的偏移混为一个定位。来源包含资产 ID、声明引用、半开字符区间 `[start, end)`，与 asset_snapshot_id 中的内容相对应；不是 UTF-8 字节偏移。

默认最多保留 6 个证据块，块长 1800 字符。无命中是正常空检索，不编造来源。为保持可审计性，不使用向量搜索、联网补充或隐式模型重排。

预算不足时先逐个移除低优先级证据，再从最旧开始移除完整用户轮次，记录排除的摘要和移除轮次数。原历史必须先通过工具协议验证：调用与真实响应配对完整，不允许孤立结果、重复并行 ID 或未完成调用通过截断消失。最新用户轮次、固定权限说明、项目说明和必留任务状态不参与移除；无法容纳时返回 blocked。单消息、消息数和请求总量限制也会明确阻塞，不截掉字段或字符串尾部。

这是一种保守的完整轮次压缩，不是语义总结；旧非必留信息可能不再出现在本次模型视图中。需要长期保持的约束应进入必留边界或经审核的项目资料。

## 真实 tokenizer 与预算

分别固定 Flash V4.1、Pro V4 的官方编码代码和 tokenizer JSON，模型绑定、commit、Git blob 摘要和大小在代码中登记；原编码字节、来源和 MIT 许可证保留于 `src/auton/context/vendor`。下载脚本只下载 JSON，不下载或动态执行远程 Python。权重目录被忽略，不推送模型/tokenizer 大文件。

计数使用完整消息模板和工具 schema，再使用对应 tokenizer，关闭 truncation/padding，并避免重复添加起始 token。当前只支持与 M04 一致的文本/chat（thinking disabled）模式。缺文件、摘要不符、无模型绑定或模板不兼容明确阻塞。

本地计数与准入预算分开：准入取“本地计数加远程余量”和 M04 保守的 JSON 字节数加 512 的较大值，另预留输出。默认远程余量 512，操作上下文上限由模型目录给出，目前 8192。保守字节门槛可能比模型真实容量更早阻塞，这是沿用的保护，不应称为模型原生窗口上限。

显式 test/mock 模型才使用带 test-fixture 标记的字节计数；真实模型没有这种 fallback。快照与事件保存计数来源，测试记录不能当真实训练样本。

2026-11-18 使用本地配置密钥、两个公开短请求，走完整 ContextEngine 装配、持久读取，再经真实 M04 gateway 调用，结果均为 `OK`：

| 模型 | 本地固定编码输入 | 远端 usage 输入/输出 | 保守准入 | 估算费用（microUSD） |
| --- | --- | --- | --- | --- |
| deepseek-flash | 213 | 213 / 1 | 1867 | 66 |
| deepseek-v4-pro | 212 | 212 / 1 | 1868 | 284 |

另外本地完整工具历史计数分别为 332/347。这两个短文本样例的差值为零，不代表所有格式或未来云端别名均完全相等。云端实际结算继续以 response usage 为准，hosted 模型版本并未被本地 tokenizer 固定。估算合计 $0.000350，不是账单价格保证。

## 快照、接口与配置

`ContextSnapshot` 保存最终 messages/tools、模型声明版本、数据域、tokenizer/固定指令/检索/压缩版本、配置摘要、asset_snapshot_id、目标修订/截止点、receipt 摘要、预算、来源和压缩说明。内容摘要形成稳定 ID，owner 哈希范围内保存请求索引与快照两个事件，批量原子追加；相同请求 ID/输入可恢复结果，改输入被拒绝。写入成功但确认丢失时重读核对，不盲目追加。

快照再次读取重新检查资产治理、receipt、配置/模型/策略版本与当前模型可用性。模型、目标修订不匹配时禁止沿用 previous_context_id，应从原始状态建立新请求。允许复现原输入不意味着绕过新的撤回或授权约束；事件本身保留审计内容，逻辑撤回不是物理擦除。

新增 API：

- `POST /api/v1/projects/{project_id}/context`：预览装配，不调用模型，不保留执行预算。浏览器仅提交 request_id、model_id、state、history 与 public 声明；principal/goal authority 由服务端构造，禁止伪造角色。
- `GET /api/v1/projects/{project_id}/context/{snapshot_id}`：读取并重新验证同主体快照。

预览 goal_revision=1、state_cutoff=0 是明确的独立预览域；真实轨迹截止点由后续 M09/M10 运行时提供。前端旧历史输入每行代表一个用户轮次，不伪造工具调用；底层 Port 支持完整工具历史。完整 API 和前端类型已生成。

可选 TOML 配置，无须数据库迁移：

```toml
[context]
tokenizer_directory = "weights/context-tokenizers"
max_evidence = 6
chunk_characters = 1800
hosted_overhead_tokens = 512
```

Context 请求总量上限 1 MiB、最多 300 条历史/16 个工具、必留边界 20 条×300 字、未决操作最多 30 个。具体字段过限由严格契约拒绝；数据库沿用 M02 通用版本化事件存储，不新增表。

## 前端与验证

上下文页面提供项目/模型选择、目标/必留边界/可选旧轮次、公开数据声明、来源定位、预算、排除/压缩说明、完整快照高级视图和重校验。加载、无项目、接口错误/权限不足、tokenizer 不可用与 blocked 原因可见；修改输入清除旧结果，不能让过期响应覆盖新输入。

- `make check`：136 个非浏览器测试；Ruff、strict mypy、14 项 Python 边界、前端边界、契约漂移检查、前端 lint/format/生产构建通过。
- `AUTON_BROWSER_CHANNEL=chrome make e2e`：10 个浏览器流程通过。M08 实际创建 Git 项目、晋升资料，短输入展示来源，长输入显示移除 15 个完整旧轮次及排除 1 个证据块，必留边界存在，快照可重校验，输入修改清除旧结果；手机无横向溢出。
- `make context-smoke`：实际官方 tokenizer 的中英文和工具历史可编码、计数稳定。
- `.venv/bin/python scripts/context_smoke.py --hosted`：上述两个真实 DeepSeek 请求，结果保存在本地忽略的 `test-results/context-smoke.json`，不包含密钥。
- 故障覆盖：长轨迹、关键状态过大、消息数上限优先移除非关键证据、恶意资料不进入 system、无检索命中、来源撤回/过期、模型/配置切换、跨项目/跨主体、工具孤立/未完成、伪造完成状态、receipt 在装配中/之后变化、写入确认丢失与请求 ID 冲突、真实模型缺 tokenizer 不回退。
