# M10：单机轨迹投影、检查点与恢复验收

日期：2026-11-18。M09 已测试并推送 `ba135f4` 后，才进入本里程碑。

## 模块边界与存储

新增 ExperienceFactory、ProjectionFactory、CheckpointRepositoryFactory、ExperiencePort/ProjectionPort。Experience 只依赖 agent/资产/上下文的公开 Port 和 M02 事件事实；Agent 不反向 import experience、评测或学习实现。

APSW SQLite 投影位于 `.auton_local/experience/projections.sqlite3`，使用 WAL/FULL；原始事实仍在 M02 EventLog。索引只保存 event ID、cursor、digest、kind、scope 标识、事件时间、处理时间及检查点引用，不复制原始 messages、principal 或密钥。查询时再从原始事件验证摘要、游标和实际 scope，缓存不能充当权限来源。

每批索引、checkpoint 引用与处理 cursor 在一个事务内提交。重复消费验证相同事件摘要并幂等跳过；中途失败整体回滚，不把 cursor 提前推进。内置 schema 1→2 升级会清空可重建索引并重投影，不删除原始事件。未知索引版本拒绝启动，不按当前版本猜测字段。

重建通过内部运维 Port 显式执行，未暴露面向浏览器的全局删除接口。重建后的事实 ID、游标、内容摘要、节点/边和 checkpoint 引用保持一致；processed_at 代表本次重新处理时间，会正常变化，不能把它伪装成原事件时间。

## 投影、关联与指标

- session/goal/run 由受控主体/项目 seed 与原始检查点关联，checkpoint 索引保存 source event ID、全局 cursor、digest、run version、runtime revision、session/goal/project 引用。
- 同一 run 按 goal_revision 形成 episode，保存起止游标、模型请求、工具操作、上下文版本和观察到的用量；parent_run_id 预留，当前没有伪造多 Agent DAG。
- 时间线记录原始事件 timestamp 与索引 processed_at。这里的事件时间是宿主事件记录时间，不是远端模型内部时钟。晚于新目标提交才入库的旧修订结果保留在原 episode，并显示 late_revision_result。
- 从历史检查点收集工具操作引用，不能因当前目标修订清空 plans 就丢掉旧操作。工具使用自己的 workspace goal；episode 归属由 run 中首次记录该计划的目标修订建立，不把两个 goal 的修订号混用。
- 判断 raw_event_id、模型/工具 reservation、context ID、receipt、宿主检查与 checkpoint 建立可核对关联。Laya 仅作为 advisory 记录，关联边不表示其路由已被采用。验收边仍带 semantic_quality_verified=false。
- receipt 关联只指向当时已经存在的源事件，不把未来对账结果回填成过去已知信息。模型 received/completed 按 request_id 去重计算观察用量，避免同一结果重复计费；确认费用仍是登记价格估算。
- run-checkpoint-version 与全局事件 cursor 是不同单位；恢复使用具体 source checkpoint event ID/version。缺失模型 intent、源事件/快照不可用、索引落后或未知用量都明确标识，缺少可读 checkpoint 时用量为 null，不写成零。

默认单次最多追赶 20000 条全局事件，每批 200 条；轨迹视图最多 2000 条事件。达到上限显示 projection_behind/trace_limit 并阻止基于不完整视图恢复，后续可刷新继续追赶。本次为请求驱动查询投影，不声称实现了 M21 常驻调度或无限轨迹分页。

## 权限与恢复

查询先核对同主体/项目 seed，再验证资产读取权限；索引中的伪造 scope 不能扩大结果集。inspect/recovery 只允许 user 控制面，training/export 或非用户角色被拒绝；API 不返回原始 principal、完整模型请求或凭据。保留的本机审计历史不等于物理删除，报告/新执行继续遵守当前来源治理。

恢复必须同时满足：原 checkpoint 摘要/游标有效、runtime revision 可读、投影追平、关键 context/判断/模型证据可定位、处于 paused/blocked 安全边界、未知工具已按账本处理。未知 checkpoint schema 可查询为不可恢复状态；Agent API 返回明确的 schema_incompatible，不能 500 后盲目继续。

RecoveryCommand 指定稳定 request_id、expected_version、expected_goal_revision 和 checkpoint_event_id。Experience 记录请求意图；Agent 在同一命令锁内再次比较版本和目标修订。视图检查之后发生并发暂停/修订，也会被最终 CAS 拒绝。重复已接收的恢复命令只返回现有状态，不重复派发；相同 ID 换输入被拒绝。

恢复仍走 M09 循环和 M03/M06/M04 门禁：暂停于审批前的任务恢复后仍等待同一操作审批；确认完成的写入从 ledger 取回 receipt；未知写入先对账；未确认模型使用原请求 ID 恢复，不能自动重发未知请求。投影不创建自己的执行器。

安全 checkpoint 的完整历史、目标/修订、待执行调用、审批/receipt、模型/判断来源和已用预算继续在 M09 原始事件中保存；M10 引用它们，展示历史消息计数、未决调用 ID、模型 intent、资产/模型/策略版本及预算摘要，不以对话摘要替代恢复状态。

## API、CLI 与界面

- `GET /api/v1/projects/{project}/runs/{run}/trajectory?purpose=inspect|recovery`。
- `POST /api/v1/projects/{project}/runs/{run}/recover`，使用版本绑定的 RecoveryCommand。
- CLI 增加 trajectory/recover，经同一应用接口，不绕过服务端检查。
- 任务页由独立 experience feature 工厂接入时间线、处理进度、确认用量/未知提示、源引用及检查点恢复。加载、失败、证据缺失、索引落后和不可恢复原因可见；旧视图的恢复按钮禁用，服务器也独立拒绝过期版本。

可选配置：

```toml
[experience]
directory = ".auton_local/experience"
batch_size = 200
max_catchup_events = 20000
max_trace_events = 2000
```

不修改 M02 原始事件表；仅增加独立可重建投影及公开 checkpoint ID/CAS 契约。浏览器/CLI 的身份仍受当前后端进程所有者集限制，持久身份与完整服务协议由 M11 完成。跨进程验收使用同一个可信应用主体，不把“刷新恢复”冒充“浏览器跨后端重启身份已完成”。

## 验证与可复现证据

- `make check`：166 个非浏览器测试，Ruff、strict mypy、18 项 Python 边界、前端边界、API/类型漂移、lint/format/生产构建通过。
- `AUTON_BROWSER_CHANNEL=chrome make e2e`：11 个浏览器流程通过；M10 覆盖暂停于写入审批前、核对 checkpoint、恢复后仍等待审批、真实文件验收、事件时间线、刷新与手机布局。最终截图定向复验通过。
- 投影重建前后事实/边/checkpoint 相同，重复消费幂等；批次约束失败回滚 cursor；schema 1→2 重投影；索引落后可见；用途/角色/跨主体拒绝；伪造索引 scope 不泄露其他 run 的元数据。
- 旧修订晚到事件保持原 episode，目标修订后历史工具计划不丢失；缺 snapshot 和未知 runtime schema 拒绝恢复；检查后并发变更由最终版本 CAS 拦截；稳定恢复 ID 幂等。
- `tests/helpers/recovery_process.py` 在两个独立 Python 进程中验证安全恢复，显式 test 模型、真实 SQLite/Git/文件工具。正常暂停后重启，以及已确认文件写入后、运行时未消费 receipt 前执行子进程 os._exit，两种情况下都继续到 succeeded，工具 started 事件均只有 1 条，receipt attempt=1。不会停止已有开发服务。
