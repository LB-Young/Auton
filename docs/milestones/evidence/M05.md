# M05：本地 Laya 判断层验收与质量限制

日期：2026-11-17。M04 已独立测试、提交并推送为 `d6d1899`。

## 当前结论

**工程接入验收通过；当前零样本 checkpoint 不满足自动决策质量要求。** 默认 `judgment.application_enabled=false`，生成和记录建议，不自动采用或执行。后续工具等独立模块可以开发，M09 启用自动执行链路前必须解决此判断质量门槛，不能把本记录当作质量验收通过。

用户要求的 Laya 已下载在本机 `weights/laya-multilingual`，约 678 MB，总计五个文件。权重被 Git 忽略，GitHub 保存下载脚本、锁定版本、校验摘要和验收结果，不上传大权重。

## 工程交付

JudgmentFactory、LayaAdapterFactory、RoutePolicyFactory 与独立 Port；判断来源固定为本地 Laya，不使用自动语言 Router，不回退托管 Jev。英语根 checkpoint、类型化 checkpoint 和当前多语言 checkpoint 不混称同一模型。

固定来源：`convaiinnovations/laya`，revision `e333cb7c823cd1787276228260f56d02fbf5180b`，subfolder `multilingual`，Laya runtime `0.3.20`，Transformers `4.57.6`，Torch `2.15.0`，本次 CPU，长度 1024。包由 uv.lock 锁定；下载脚本校验 LFS SHA256 / Git blob 摘要，生成完整 SHA256 manifest。仅下载权重与 JSON，不下载/执行 checkpoint 仓库的 Python 代码。

- 稳定 question/option ID、问题版本、choice/boolean/score 契约、状态截止点、目标修订、输入摘要、真实来源与原始事件引用完整记录。
- 初始判断点：信息充分性、执行档位、工具领域与工作模式。工具/Skill 结果目前仅为建议，没有已安装 Skill 匹配或工具授权能力。
- 固定策略过滤能力、上下文、健康、外发 provider 与数据域，再按满足档位的候选选型；2B/7B 是需求档位，当前没有注册本地执行模型，必要时明确记录更强的允许候选或阻塞。
- 主判断来源与执行模型路由分开；评分和 `act_probability` 不转成任务成功率、权限或训练真值。
- 原始响应、每个问题的成功/失败/弃权、路由建议、采用/拒绝记录分开。默认 preview 均未采用。可信运行时 apply Port 需显式打开固定配置，复查目标/策略/候选/状态截止点后才记录选择动作；它本身仍不派发模型或工具。
- 晚到结果保留原始响应，标 stale。相同请求重放不重新推理，输入不同拒绝；中断状态保留，需要新请求 ID。部分问题坏 schema 不擦除其他答案。
- 本地 worker 不继承 API key/代理；离线环境加载已有文件。真实 tokenizer 预检拒绝截断，不把丢失约束的输入悄悄交给模型。超时/取消杀掉本次拥有的 worker，避免原生推理残留；这不是 OS 沙箱。

## 实测与误判证据

- `make check`：87 个非浏览器测试、mypy strict、8 项 Python 边界、前端边界、OpenAPI 类型漂移、lint/format、生产构建通过。
- `AUTON_BROWSER_CHANNEL=chrome make e2e`：7 个浏览器流程通过，测试配置显式 Mock，不访问云端或加载权重。
- 额外真实本地浏览器预览通过，来源显示 Laya，建议/未采用清楚可见；未调用执行 provider。[真实页面](./M05-assets/laya-real.png)。
- `scripts/judgment_smoke.py`：六条中英手工开发样例，各四个判断，以及一次选项反排。当前档位正确 **3/6**，信息充分性正确 **3/6**；反排后的简单任务仍返回稳定 `small_2b` ID。单次重排不能证明普遍顺序不敏感。
- 本机首次请求含加载约 2.6 秒，后续六例的热请求约 79–99 ms；仅当前短输入/CPU，不可外推吞吐。
- 明确错误：`1+1` 任务被高分判为信息不足；复杂架构/分布式协议任务被低估为 7B 档位。原始输出和误判没有删除，见 [完整小样本记录](./M05-assets/laya-smoke.json)。该集合不是盲测或发布评测，不据此宣传质量。
- 故障测试覆盖：缺权重、坏 schema/概率分布、选项 ID、批量部分失败、高分不越权、私密外发过滤、能力/上下文/档位过滤、修订后迟到、状态截止点变化、失败重放、繁忙、取消、worker 超时与不继承凭据。

## 接口与后续

`GET /api/v1/judgment`，`POST /api/v1/judgment/preview`；浏览器只能提交状态和明确 public 标记，主体与四个问题由服务端构造。模型页提供独立本地预览，主对话仍为 Demo。真实任务侧栏接 M09/M12；没有虚构现阶段不存在的任务。

运行 `make judgment-setup` 安装可选依赖并下载验证；`make judgment-smoke` 做显式本地基线。普通 `make setup/check` 和 CI 不依赖大权重。`test` profile 明确要求 Mock judgment，其他 profile 禁止 Mock。新事件沿用 M02 schema，无数据库迁移。

下一步质量工作：建立领域标签/独立开发与保留集、核对问题表达、必要时训练或校准候选，再走 M13/M19/M20 的独立评测与发布门禁。在此之前保持建议模式，不因连接成功打开自动采用。
