# M15：资产诊断、候选补丁与独立门禁

2026-11-19，分支 `claude/project-architecture-review-f9de4i`。

## 已交付范围

`EvolutionFactory` 组装诊断、可优化字段、单次反思、固定门禁和隔离执行器；调用方使用 `EvolutionPort`。优化器只持有资产读取、arena 快照与学习候选写入能力，没有正式资产发布 Port。运行时也不能反向导入进化实现。

流程：用户选择报告 → 假设诊断 → 提出单个 Markdown Skill 小节补丁（可选一次强模型反思）→ 查看局部 diff → 冻结 train/development、模型、预算、检查点与重复次数 → baseline/candidate/ablation 独立工作区执行 → 逐次审批文件改动 → 独立验收和固定门禁 → 用户审核方向 → 仅写入 learning 候选。

- 诊断区分工具/环境、执行能力、信息不足和资产假设。错误交付不等于已证明 Skill 是原因；过期报告不能进入反思。
- 字段按唯一 ATX 标题定位，识别 fenced code；校验完整父文本 SHA 和旧正文，保留小节外原文。默认最多 1,500 字符、全文件 50% 的一个连续改动区域。禁止越界标题、未闭合代码块、连接后续标题、过度精简、凭据和超长资产。
- Playbook 保留失败、阻塞、重复和待审核的原因及父版本。全文精确重复与词法近似重复分别检查；词法启发式不是语义 embedding。相同父资产的失败变异有上限，同一提案最多三次结束/阻塞后的评测。
- 反思最多一次、严格 JSON `new_body/rationale`、无工具及自评分，只看到 train 摘要和先前方向；dev/test/meta 不进入生成。输入与输出、单次预估费用均有界。模型身份、指纹、派发、实际用量及未知费用独立保存；模型失败不抹掉已知消费。
- 当前 arena 仅支持文件型任务和 `file.write`。任务、模型、价格、工具、预算、其他资产和项目指令必须相同，只允许目标 Skill 的原文、候选或移除三种输入变化。整个计划在调用前冻结，预检总调用/tokens/费用/工具上限；远程执行要求每个案例公开且用户显式设置 `public=true`。
- 目标 Skill 必须出现在实际 ContextSnapshot 首次输入证据中，工具参数检查点由用户先行冻结。验收使用 M13 独立文件 SHA/协议检查，不能让候选编写 checker 或修改验收目标。

## 门禁与边界

| 门禁 | 固定证据 |
| --- | --- |
| G1 | 单小节结构、范围、长度、父版本 |
| G2 protocol | 完整三分支计划、同条件签名、真实执行器身份/指纹/价格、环境和用量 |
| G2 regression | 核心案例、严重失败、用户工具参数检查点 |
| G3 | 至少三次重复、至少三个独立开发集家族、家族配对单侧 sign test p≤0.05、无候选开发集失败、费用不超过基线 5% |
| G4 | 去掉 Skill 的消融增益、实际输入保留 Skill、历史重复方向 |
| G5 | 独立用户方向审核 |

独立组按 family、origin_group、规范化 prompt 连通分组，重复轨迹不冒充独立样本。三个家族全胜也只有 p=0.125，不能宣称显著改进；五个独立家族全胜 p=0.03125。该规则适用于当前受控文件案例，不能据此推断开放领域语义质量。

硬失败不能提交 learning；只有 HOLD 的候选可经用户审核进入 `review_queue`，全部门禁通过才标记 `ready_for_release`。两者都 `activation=not_activated`。Genome 通用 promote 对 `evolution-proposal:` 来源明确拒绝，后续 M20 必须提供独立发布能力和最终测试证据。

## 持久化、幂等与恢复

私有 `evolve.directory/evolution.sqlite3`，schema 1，WAL/FULL、目录 0700/文件 0600、进程独占锁、不可变版本、CAS head 和请求回执同事务。主事件日志只写此模块的元数据与摘要，不写候选正文。评测案例、变异和命令原文保存在独立进化库；Agent 的实际输入仍按执行轨迹审计，M17 必须排除 `optimization_arena` 轨迹，不能混入 executor/decision 训练。

所有付费动作、创建、批准和 learning 写入都有固定 request id。学习写入已提交但响应丢失时，重试核对同来源同内容候选，复用原 Git revision，不覆盖其他待审核资产。重启不自动继续模型调用或审批；孤立的进行中 arena 变 blocked，显式恢复或取消。即使银行/配置已变化，取消仍根据原冻结输入定位并停止已创建子任务。未知模型/工具副作用保持 blocked，不能靠另建任务消除未知记录。

父资产撤销使候选与移除 Skill 的快照都失效。正式资产、评估银行/配置、目标、运行版本、输入或实际交付发生变化时拒绝继续/提交；历史 pass 不等于当前证据仍有效。M13 新增 `current_evidence_valid`，同时修复资产输入快照未绑定候选版本的问题，checker revision 更新为 `deterministic-checks-v2`，旧报告不能沿用为新的可信证据。Agent runtime 仍为 v3，旧字段兼容读取。

网关还修复了失败请求的重放阶段优先级：已派发未知请求不能因重读记录变成未派发/零费用；已记录的失败用量会被保留。

## 前端与 API

入口 `?view=evolve`（侧栏“进化”），项目隔离、诊断/局部补丁/反思/冻结评测命令编辑器、候选 diff、门禁、逐次实际文件差异审批、费用与未知调用、Playbook、生成记录和方向审核。支持加载、空、错误、重载和手机布局。模型调用默认不自动开始，公共例子的 `public` 默认 false。

`/api/v1/evolution/` 下提供 `status`、`diagnoses`、`proposals`、`reflections`、`generations`、`playbook`、`arenas`、`arenas/{id}/commands`、`proposals/{id}/submit`。身份来自服务端 session，角色不能由请求正文伪装。OpenAPI/TypeScript 自动生成；配置 `[evolve]`，默认反思注册模型 `deepseek-v4-pro`，可指定其他已注册且允许的模型。
