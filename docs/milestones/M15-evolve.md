# M15：资产诊断、候选补丁与门禁

> 状态：计划中。当前仅建立开发计划，未实现本里程碑。

## 目标与前置依赖

先跑通可解释的资产改进闭环，再扩大自动优化。

前置：M07、M13。M01 必须先完成；其余按依赖验收后进入。

## 模块与工厂

EvolutionFactory、DiagnoserFactory、MutationStrategyFactory、GateFactory。对外 Port、配置、实现选择、依赖注入与生命周期遵守 [工厂规范](./module-factory-contract.md)，调用方不得依赖具体 adapter。

## 开发任务

- [ ] 从证据识别工具故障、资产缺陷、执行能力缺口与信息不足，不能所有错误都修 Prompt。
- [ ] 实现 Playbook、可优化字段、局部 diff 与一种反思策略；预算内生成候选而非整体重写。
- [ ] 按既有架构实现适用的 schema/回归/同预算验证/方向门禁与 lineage，候选隔离保存。
- [ ] 先支持人工提出→隔离评测→查看 diff→提交待发布，后续按收益加入自举与搜索策略。

## 前端交付

资产诊断、候选 diff、门禁报告、Playbook 与待审核列表。页面遵循 [前端规格](./frontend-design.md)，具备加载、空、失败、不可用与权限不足状态。

## 验收条件

1. 用一个受控 Skill 改进案例跑通候选到评测报告，失败候选被保留原因。
2. 候选不能修改权限、checker、holdout 或正式 main；差异有来源与适用范围。
3. 新候选不因生成完成自动生效，发布留给 M20。

## 必验故障

修改裁判、奖励投机、预算不公平、候选重复、过度精简、方向漂移。针对行为做契约/集成或端到端验证，交付可复现步骤与结果。

## 范围与完成证据

先单策略和人工闭环；复杂策略、Dreaming 调度待证据与 M21。

交付实现、相关检查结果、接口/配置/迁移说明和页面演示；由验收证据更新 [总表](./README.md)，不以 Mock 通过替代真实模块完成。
