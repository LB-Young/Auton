# Auton 前端：对话工作台与任务控制面

> v0.1，2026-11-16。M01 必须提供可操作的前端骨架；后续模块各自完成对应页面。M01 对话/产物工作台骨架现已实现，见 [验收记录](./evidence/M01.md)；后续真实业务交互仍按各模块落地。

## 1. 参考与定位

参考 ChatGPT 的项目组织与会话工作流，以及 Claude 的对话结合产物工作区。官方资料用于理解交互模式，不复制品牌、配色、商标或声称还原某个日期的完整界面。

- [ChatGPT Projects 原始资料](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)：参考项目内组织聊天、文件和说明。[阅读笔记](../references/chatgpt-project-workspace-ui.md)
- [Claude Artifacts 原始资料](https://claude.com/features/artifacts)：参考对话围绕可查看、编辑的产物迭代。[阅读笔记](../references/claude-artifact-workspace-ui.md)

Auton 主路径是“发任务 → 看进度与产物 → 必要时介入 → 交付”，学习、评测和发布作为独立工作区，避免主聊天窗口充满运维信息。

## 2. 页面结构

```text
┌──────────────────┬────────────────────────────┬────────────────────┐
│ Auton / 新对话    │ 项目 / 会话标题   任务状态  │ 按需展开的工作面板 │
│ 搜索             ├────────────────────────────┤                    │
│ 项目             │ 用户消息                   │ 产物 / 执行步骤    │
│  最近会话        │ 助手回答 / 引用 / 工具卡片  │ 决策记录 / 子任务  │
│                  │ 审批请求 / 错误与恢复提示   │ 文件预览与差异     │
│ 工作区           │                            │                    │
│  任务 / 资产     ├────────────────────────────┤                    │
│  模型 / 学习     │ 附件  任务输入             │                    │
│  评测 / 发布     │ 能力提示   发送 / 停止      │                    │
│ 设置 / 连接状态  │                            │                    │
└──────────────────┴────────────────────────────┴────────────────────┘
```

桌面左侧导航可折叠，主对话保持阅读宽度，右侧面板可调整并关闭。中屏最多同时打开一个辅助面板；手机使用导航抽屉、全屏产物与底部输入，主操作在 390px 宽度下无横向溢出。复杂日志只在诊断视图展开。

视觉采用中性背景、清晰文字层级、适量留白与一个强调色，提供明暗主题；状态同时使用文字/图标，不只依赖红绿颜色。字号、间距、边框、面板宽度和动效形成 token，不让页面各定一套。

## 3. 工作区与模块归属

| 工作区 | 用户要完成的事 | 负责里程碑 |
|---|---|---|
| 对话 | 新建/恢复会话，发消息，停止、继续、反馈 | M01 骨架，M09/M11/M12 接真 |
| 项目 | 管理项目边界、会话、资料与项目说明 | M07/M11/M12 |
| 任务 | 看 goal/run 状态、阻塞原因、待审批项、子任务 | M09/M10/M14 |
| 产物侧栏 | 查看文件、报告、补丁与版本、定位来源 | M06/M09/M12 |
| 资产 | 浏览 Skill、记忆、Prompt、role 版本与来源 | M07/M08/M15 |
| 模型与判断 | 执行候选、Jev 状态、判断输入/结果/版本 | M04/M05/M19/M20 |
| 评测 | 启动获准评测，比较候选、分组与证据量 | M13/M19 |
| 学习 | 审核样本、KEEP/DROP/HOLD、数据谱系与训练作业 | M16/M17/M18/M19 |
| 发布 | 查看范围、报告、批准、灰度、暂停与回滚 | M20 |
| 设置与运行 | 连接、隐私、资源窗口、预算、后台健康 | M03/M11/M21 |

M01 导航可展示未来工作区，但标“待开发”，入口显示解释页，不制造假数据或可点击但无响应的操作。主界面显示当前可用能力，只有 Demo 环境使用模拟任务。

## 4. 关键交互

### 对话与执行

输入区支持多行、附件入口、发送与停止；中文输入法 composing 时 Enter 不误发送，默认 Enter 发送/Shift+Enter 换行并可配置。附件未开发时明确说明，不做无反馈按钮。

消息包含 Markdown、代码块复制、来源链接和版本化产物卡片；工具执行展示“将做什么/进行中/结果/需介入”，只展示公开步骤与证据摘要，不要求展示隐藏思维链。主区只显示当前关键状态，完整过程到侧栏。

停止是服务端可追溯命令：点击后先显示“正在停止”，收到确认才显示已停止；关闭页面或断流不等于任务取消。服务端重复命令按 request_id 去重，发送重试不创建两个 run。

用户修订保存新 goal_revision；旧运行结果迟到不能覆盖新目标。重新生成或编辑历史产生分支/新 run，保留原记录，不能静默改写审计历史。

### 审批与结果

审批卡显示具体动作、目标、范围、预期副作用与期限，支持批准/拒绝和理由；按钮绑定 approval_id 与 goal_revision。权限由服务端验证，前端隐藏按钮不等于授权。

最终交付关联真实 artifact 与验收状态。“生成完成”“已验证”“已提交/发布”分别展示；无 receipt 不显示已写入外部系统。失败展示可操作的阻塞原因，不用模型口头成功覆盖工具错误。

### 学习与发布

数据表可按来源、判断点、评审状态、版本筛选，点入查看决策前状态、实际动作、后续证据和排除原因；DROP 从训练排除与物理删除分开操作。

模型页明确“执行模型”和“决策模型”。Jev-only 阶段不能用模型下拉框启用本地 student。候选、离线通过、影子、待批准、灰度、已激活是不同状态；未来激活入口展示范围和报告，绑定 M20 发布权限。

## 5. 前后端契约

首期采用 HTTP 命令/查询与 WebSocket 事件流，API 版本前缀 `/api/v1`。明确命令响应、业务完成和事件到达是不同时间；接口 schema 从后端生成前端类型，不手写两套字段。

事件信封至少包含 event_id、sequence/cursor、session_id、goal_id、run_id、goal_revision、kind、schema_version、timestamp、payload。持久事件支持游标续传与去重；文本 delta 可为临时流，最终消息和状态快照必须可重新查询。不能承诺断流时每个 token 都被保存。

重连先对齐持久快照与游标再接增量；倒序/重复/缺口有明确处理，UI 不把断流标为任务失败。服务端暴露 capabilities，未实现模块统一返回明确错误；Mock profile 不能在生产请求失败时自动启用。

API key 只在后端或受控 secret 存储；不写入前端包、localStorage、分享链接或日志。上传、Markdown、HTML 预览按不可信内容处理，HTML 在受限 sandbox 展示；文件读取通过 artifact ID 与授权 API，不接受任意系统路径。

## 6. 前端工程与工厂模式

推荐 React + TypeScript + Vite，具体稳定版本在 M01 锁定，所有工具版本写入 lockfile 与启动说明。React 用于组件化界面，Vite 用于开发/构建；不要因参考 ChatGPT/Claude 而引入无关托管依赖。[React 笔记](../references/react-component-ui.md) · [Vite 笔记](../references/vite-web-tooling.md)

```text
clients/web/src/
  app/             # 启动、composition root、路由、主题、边界
  shared/          # UI token、基础控件、通用类型
  transport/       # ApiClientFactory、EventStreamFactory
  features/
    chat/          # ports、factory、controller、views
    projects/
    runs/
    artifacts/
    genome/
    models/
    evaluation/
    learning/
    releases/
    settings/
```

feature 之间只经公共接口与应用路由协作，不能互相读内部 store。服务端状态与输入草稿/面板开关分离；恢复状态以服务端为准，schema 不匹配有明确升级提示。

## 7. 验收层次

- M01：在 Mock profile 演示新会话、发送、流式显示、停止确认、产物面板、导航、主题切换；刷新后的 Demo 持久范围在说明里写清，不伪装成服务端持久化。
- M09–M12：真任务、真实事件、刷新恢复、断线续接与错误反馈取代模拟；模型不可用不能返回 Mock 成功。
- 模块交付：每一页具备加载、空数据、成功、失败、权限不足、不可用状态；有危险动作的页面做操作确认和服务端校验。
- 可用性：键盘焦点、屏幕阅读标签、中文输入法、长代码/长列表滚动、流式更新不抢焦点；用户向上阅读时不强制滚到底部。
- 验证：桌面与窄屏截图/操作记录，核心流程浏览器端到端检查，重连/重复消息/迟到审批等有对应故障用例。

M01 已交付框架演示页面与后端 API；完整真实业务能力仍由 M02–M21 逐模块接入，不能把界面已存在当业务已完成。
