# M02：核心内核与事件持久化

> 状态：已完成（2026-11-17，本地验收通过）。见 [验收记录](./evidence/M02.md)。

## 目标与前置依赖

统一标识、事件、错误和持久状态基础，使后续模块可回放、可恢复。

前置：M01。M01 必须先完成；其余按依赖验收后进入。

## 模块与工厂

KernelFactory、EventLogFactory、ClockFactory。对外 Port、配置、实现选择、依赖注入与生命周期遵守 [工厂规范](./module-factory-contract.md)，调用方不得依赖具体 adapter。

## 开发任务

- [x] 定义 Goal/Task/Run/Attempt/Operation 标识、goal_revision 和版本化事件信封；共享类型不塞入业务策略。
- [x] 实现 SQLite WAL EventLog、migration、事务追加、稳定游标与幂等事件写入；内存实现仅用于测试。
- [x] 建立 Clock/ID/事务 Port、应用生命周期与结构化错误；恢复时区分未提交、已提交和未知结果。
- [x] 明确原始数据、投影、artifact 引用的存储位置与保留策略，记录 schema 升级兼容范围。

## 前端交付

连接状态与持久化能力由 capabilities 返回；Demo 内存与真实数据库明确区分。页面遵循 [前端规格](./frontend-design.md)，具备加载、空、失败、不可用与权限不足状态。

## 验收条件

1. 追加后进程重启能按序读取；同 event_id 重试不产生重复事实。
2. 迁移前后记录可读取，失败迁移不破坏原库；损坏/不支持版本明确拒绝。
3. Clock/存储工厂可替换，业务调用方不依赖 SQLite 细节。

## 必验故障

断电边界、重复追加、游标缺口、数据库锁/磁盘满、迁移失败。针对行为做契约/集成或端到端验证，交付可复现步骤与结果。

## 范围与完成证据

只构建内核与事件存储；业务投影、完整会话恢复在 M10/M11 完善。

交付实现、相关检查结果、接口/配置/迁移说明和页面演示；由验收证据更新 [总表](./README.md)，不以 Mock 通过替代真实模块完成。
