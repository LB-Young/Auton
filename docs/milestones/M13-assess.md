# M13：独立评估、可信信号与校准

> 状态：工程验收通过；真实人工金标校准缺失，语义可信门禁关闭。详见[验收证据](./evidence/M13.md)。

## 目标与前置依赖

建立业务验收、判断评估和可校准裁判，为优化与训练提供独立依据。

前置：M03、M10。M01 必须先完成；其余按依赖验收后进入。

## 模块与工厂

AssessFactory、CheckerFactory、JudgeFactory、EvalStoreFactory。对外 Port、配置、实现选择、依赖注入与生命周期遵守 [工厂规范](./module-factory-contract.md)，调用方不得依赖具体 adapter。

## 开发任务

- [x] 区分确定性 checker、模型 judge、人工标签和未核验自述，记录证据来源与分歧。
- [x] 建立 train/development/test/meta 的用途权限、任务家族隔离、盲测窗口和不可变评测配置。
- [x] 构建种子任务与故障集，评估成功、返工、成本、协议、关键分组；不以单分数覆盖严重错误。
- [x] 强 reviewer/judge 使用人工元评测校准；版本化 rubric、重复试验方案和证据置信范围。

## 前端交付

评测任务、运行状态、候选对照、分组报告与证据详情；未知样本明确排除准确率分母并报告数量。页面遵循 [前端规格](./frontend-design.md)，具备加载、空、失败、不可用与权限不足状态。

## 验收条件

1. 评测者不能被优化/训练模块修改，test/meta 不泄漏给候选生成器。
2. 同条件可复验，环境故障、未知和任务失败区别记录。
3. 报告包含样本量、分组、质量与成本，不以 judge 自信当正确证据。

## 必验故障

自评偏置、test 污染、judge 漂移、少样本零错误、成功但绕路、失败非归因。针对行为做契约/集成或端到端验证，交付可复现步骤与结果。

不自动训练裁判或拿待训练 student 给自己标 gold。

交付实现、相关检查结果、接口/配置/迁移说明和页面演示；由验收证据更新 [总表](./README.md)，不以 Mock 通过替代真实模块完成。
