# M20：统一发布控制面、灰度与回滚

> 状态：发布控制面与真实运行消费链路工程实现；真实模型上线和生产质量需在目标部署环境验收。证据见 [M20](./evidence/M20.md)。

## 目标与前置依赖

以独立发布通道激活已获准的资产/执行模型/决策模型，控制实际影响范围。

前置：M13、M15；模型发布另需 M18 或 M19。M01 必须先完成；其余按依赖验收后进入。

## 模块与工厂

ReleaseFactory、GenomeReleaseFactory、ModelReleaseFactory、RolloutPolicyFactory。对外 Port、配置、实现选择、依赖注入与生命周期遵守 [工厂规范](./module-factory-contract.md)，调用方不得依赖具体 adapter。

## 开发任务

- [x] 分开定义 Genome 与 Model 状态机/写权限，复用发布报告、批准、范围、审计和监控 Port。
- [x] 发布不可变 bundle；校验模型、state builder、schema、校准与策略相容，预热成功才原子切指针。
- [x] 执行模型使用固定 goal 分组灰度；决策学生仅 offline 登记，线上保持 teacher-only，生产接手待新授权及四层实证。
- [x] 实现门槛监控、暂停/回滚、安全 checkpoint 对账；回到 Jev 仍须满足隐私与可用性。
- [ ] 决策学生未来接手后的 Jev 控制任务/live shadow：当前不启用，四层实证和明确接手授权仍缺失。actor/teacher/reviewer 来源继续区分。

## 前端交付

发布报告、范围/风险、批准、灰度比例与任务量、监控、暂停和回滚入口。页面遵循 [前端规格](./frontend-design.md)，具备加载、空、失败、不可用与权限不足状态。

## 验收条件

1. 未经批准或报告范围不匹配的候选不能激活；自动训练不获得发布权。
2. 同一任务有一个有动作权的判断来源，不双写；严重事件立即停扩量。
3. 回滚恢复完整相容配置，不重复操作；Jev 影子不继承本地成功标签。

## 必验故障

批准后 bundle 被替换、预热失败、切换竞态、共享记忆污染、回滚时 Jev 不允许外发。针对行为做契约/集成或端到端验证，交付可复现步骤与结果。
