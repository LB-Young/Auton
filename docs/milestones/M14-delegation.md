# M14：多 Agent 委派与结果集成

> 状态：已完成（受控文件 supervisor-worker 与真实成对验收）。详见[验收证据](./evidence/M14.md)。

## 目标与前置依赖

在单 Agent 可信运行基础上实现受限委派，解决共享写入和功劳归因。

前置：M06、M09、M10、M13。M01 必须先完成；其余按依赖验收后进入。

## 模块与工厂

DelegationFactory、RoleFactory、WorkspaceLeaseFactory、ResultIntegratorFactory。对外 Port、配置、实现选择、依赖注入与生命周期遵守 [工厂规范](./module-factory-contract.md)，调用方不得依赖具体 adapter。

## 开发任务

- [x] 子任务契约包含目标、范围、依赖、预算、权限、输入快照、交付和验收；父子关联进 DAG。
- [x] 实现角色与执行模型注入、有限并发、取消传播、重复委派去重和超时状态。
- [x] 工作区/文件写租约与合并集成独立管理，只有获准写入者提交动作；子任务不自己批准结果。
- [x] 集成者对照父目标验收，记录交互影响组与冲突；无法分离贡献时不给每个判断机械奖惩。

## 前端交付

任务 DAG、子任务卡、依赖/阻塞/预算和集成差异；主对话仅展示关键进展。页面遵循 [前端规格](./frontend-design.md)，具备加载、空、失败、不可用与权限不足状态。

## 验收条件

1. 同一受控任务的单/多 Agent 对照记录总成本与收益，不以更多调用宣称提升。
2. 两个子任务冲突时能阻塞/整合而非覆盖；父取消能停止新委派并处理未决操作。
3. 子权限和预算不能超过父范围，结果可追溯。

## 必验故障

重复委派、循环依赖、共享文件冲突、子任务失联、父修订目标、子成功但集成失败。针对行为做契约/集成或端到端验证，交付可复现步骤与结果。
