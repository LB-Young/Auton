## 核心观点

官方讨论将整个业务决策塞入一个巨大 Choice 问题的缺点，主张把可判断的问题拆开，让代码组合判断与规则。

## 我的理解

“任务复杂”是经验判断，“本条数据禁止外发”是权限事实。若把它们一起交模型选择，判断错误可能变成越权。拆开后可以独立测试问题质量和固定边界。

## 对 Auton 的启示

- Jev 判断任务类型、信息充分性和推理需求；代码执行能力过滤、隐私限制、授权和预算。
- 明确判断不能覆盖固定规则，角色或提示不能给自己增权。
- 多个判断可能互相不一致，RoutePolicy 应有冲突处理与 abstain，不默认它们构成正确计划。
- 为每个问题单独留评测标签，定位错在判断还是策略组合。

## 局限与验证

这是产品设计观点，不是独立算法证据。通过高置信错误、矛盾输出和故障 fallback 测试，验证系统仍遵守硬约束；不能因为 schema 正确就判整个决策可靠。
