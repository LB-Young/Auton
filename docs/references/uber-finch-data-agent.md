## 核心观点

Finch 使用 supervisor 与数据/文档专家，分别评测路由、子 Agent 和端到端。相似工具会造成意图碰撞；SQL 关注结果等价，不要求文本一致。

## 关键机制与做法

- 历史问题用于回归，专家能力与路由单独检查。
- 按需人工验证在该文章中属于后续计划。

## 我的理解

我的理解是准确率应分解到决策链。选错数据源与正确数据源上查错，需要不同修复；空结果也不能自动证明业务事实不存在。

## 对 Auton 的启示

- role 写明输入范围、数据源、返回契约和澄清条件。
- 数据库结果核对时间、单位、过滤与权限，人工复核结果有明确状态。

## 局限与适用前提

产品架构说明不提供所有失败率；规划功能不能当已实现，更不能以财务任务替代通用助手评测。

## 建议验证（尚未执行）

同名业务词分别需要不同数据源，加入无适用专家的任务，输出路由与专家错误矩阵。
