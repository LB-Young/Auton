## 核心观点

1. 评测、记忆、Self-Improve 在多数团队里被拆开做，环节之间的数据通路是断的，所以飞轮转不起来。
2. 自进化分三层：Artifacts（改产出）、Harness（改配套：记忆、Skill、Prompt、工具配置）、Model（改权重）。Harness 层"即时、可控"，是当前投入产出比最高的主战场。
3. 三条原则：**评测的可信度 > 系统的复杂度**；**记忆系统是治理问题，不是存储问题**；**闭环的价值在环节之间的衔接**。

## 关键机制

**评测（信号）**
- 评测的三重职责：方向指引、质量门控、经验筛选。错误的正反馈会让 Agent 自信地学到错误经验。
- 七大难题：弱评估器（最致命）、评什么维度（过程 vs 结果）、评什么粒度、开放式任务难量化、评测集漂移、预算公平性、评测成本。
- 分层评测：规则 / 自动校验（底层，全量）→ LLM-as-Judge（中层）→ 人工抽样 + 元评测集（顶层）。Judge 与生成模型分离、temperature 0、结构化输出、分维度独立评估。
- 评测集三分：train（诊断）/ val（筛选，不暴露给生成修复方案的 LLM）/ test（终验）；建议比例 50–60 / 20–30 / 15–20，按问题类型分层抽样。
- 评估器校准四机制：人工校准（Cohen's Kappa）、多评估器交叉、元评测集、无泄漏诊断。
- Skill 四层验证：对照实验（有/无 skill）、难度校准、轨迹追踪（是否真的按 skill 执行）、路径验证。
- 诊断归因后按类型分流：系统性问题 → 改 Skill/Prompt + 写 Playbook；偶发个例 → 写入记忆作反例；能力缺口 → 补工具 / Auto-Research；回归 → 立即回滚并标记 blocked；全部通过 → 加入金标集。
- 血泪教训：某场景连续 3 轮失败率 80%+ 且不降，先查工具实现层，配置层的进化解决不了工具层的 bug。

**记忆（积累）**
- 三环矛盾：写入（沉淀什么）、存储（怎么治理）、读取（怎么用）。
- 写入"策展而非全存"：只有明确正信号才写入长期记忆；失败经验以反例形式保存。
- 三级晋升：`.learnings/`（临时捕获）→ `MEMORY.md`（项目记忆）→ `skills/`（独立技能）。
- 不对称淘汰：好经验强化 +0.05，坏经验淘汰 −0.12。
- 分层存储（程序性 Skill / 语义 Facts / 情景 Episodes）+ 生命周期管理（版本、来源、主动遗忘、冲突解决）。
- 读取"渐进披露 + 严格预算"：默认注入顶层（约 500–800 token），按需检索中层，需要时才钻取底层；分层 token 预算（Skill ≤ 2000、Facts ≤ 800、Profile ≤ 500、单条 ≤ 200）。

**落地（工程化）**
- 自动化 ≠ 全自动：自动化覆盖"生成候选 → 评测验证 → 门控筛选"，关键决策必须有人把关。
- 八个环节：诊断归因 → 信号汇聚（本轮诊断 + 历史 Playbook + Auto-Research）→ 生成候选（Diff 模式、N 个候选）→ 独立评测（隔离环境）→ 安全门控（五层）→ 灰度发布（10% × 7 天）→ 监控回流 → 经验沉淀。
- 五层门控：语法/AST → 回归测试 → 统计显著性 → Playbook 一致性 → 人工确认。前四层自动过滤 95% 低质量变体。
- 版本化一切：版本号、变更日志、来源标记、关联评测结果。
- Dreaming：异步进程定期审阅历史会话，发现跨会话的系统性模式，输出修订建议，由人决定。

**控制（人机协作）**
- 分级自主 L0–L3，动态升降级（连续 3 个月评测通过率 > 95% 且无 P0 回归可升级；出现 P0 回归自动降级到 L1）。
- 五个必须有人的节点：规则级记忆写入前、Prompt/Skill 更新的最终确认、回归时的决策、新领域冷启动、安全边界设定。
- 审核疲劳的三层解法：自动化前置过滤、批量异步审核（做选择题）、渐进放权。
- 对齐漂移的三层防护：定期方向性审计、方向性约束指标、评测集中显式包含"意图对齐"维度。

**落地路线**：Phase 1 最小闭环（手动跑通）→ Phase 2 半自动化 → Phase 3 飞轮运转 → Phase 4 元进化。核心建议：先跑通 Phase 1。

## 局限

- 面向团队级生产系统（流量大、有业务指标），个人 Agent 流量小，"10% × 7 天"灰度难以积累样本。
- 文中引用的若干外部报告和数字未给出可核验的出处，Auton 只借鉴方法，不引用数字。
