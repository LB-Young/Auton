## 核心观点

大量工具描述与中间结果占用上下文，代码执行可让 Agent 按需发现接口、先处理数据，再把必要结果返回模型。

## 关键机制与做法

- 确定性过滤和组合调用在执行环境内完成。
- 工具不是必须全部直接暴露成模型当轮的调用选项。

## 我的理解

我的理解是减少模型搬运信息的次数，而不是减少审计。一个脚本可隐藏很多业务操作；若只记录脚本退出码，恢复和授权反而更难。

## 对 Auton 的启示

- 代码模式通过受控 API 调用工具，逐项保留授权和 operation。
- 批量只读与批量写入分别定义策略，大结果以 artifact 引用交付。

## 局限与适用前提

上下文节省不等于副作用安全，代码执行本身引入环境、资源与供应链责任。

## 建议验证（尚未执行）

脚本在第 N 次操作后异常，检查已执行项目可核实、未知项目不盲目重放。
