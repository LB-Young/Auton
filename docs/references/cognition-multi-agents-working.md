## 核心观点

后续经验将范围收窄到多个 Agent 提供判断、写入仍受控的协作。文章也指出独立代码审查不一定应该继承实现者全部背景。

## 关键机制与做法

- 实现与审查可以循环，但需要不同上下文安排。
- 只读专家与单写入主线降低了同时做出冲突修改的机会。

## 我的理解

这篇并不是简单推翻上一篇，而是区分“共同做判断”和“共同修改状态”。完整背景有助于执行，隔离背景则可能帮助验证者避免被实现理由带偏。

## 对 Auton 的启示

- 为 worker 和 reviewer 设置不同输入契约；审查先看规格和实际产物。
- 审查问题必须有位置、影响和验证方式，限定轮次并保留最终裁决责任。

## 局限与适用前提

厂商内部经验不等同于受控消融；不能把审查收益或模型独立性直接推广到所有项目。

## 建议验证（尚未执行）

比较共享实现说明与独立规格审查，对真实缺陷、纯风格意见分别测误报和漏报。
