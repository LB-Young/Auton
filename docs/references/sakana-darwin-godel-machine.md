## 核心内容

- 理论上的 Gödel Machine 要求先**证明**自修改有益，不现实；DGM 改为**经验验证**：在编码基准上实测改进是否有效。
- 三个能力：读取并修改自身 Python 代码（新增工具、改变工作流）；在 SWE-bench / Polyglot 上评测新版本；把新 Agent 加入不断增长的**存档**，后续修改可以从存档中的任何 Agent 分支出去。
- DGM 自己发现的改进：补丁验证步骤、更好的文件查看、增强的编辑工具、生成多个方案并排序选优、**记录以前尝试过什么以及为什么失败**。

## 数据

- SWE-bench：20.0% → 50.0%；Polyglot：14.2% → 30.7%。
- 消融：去掉自我改进、或去掉开放式探索（只从当前最优分支），效果都明显变差。
- 最终最优 Agent 的谱系中，有些祖先比父代表现更差，但它们是后来突破的"垫脚石"。
- 改进可迁移：用一个模型优化出的 Agent 设计换成其他模型也有提升；只在 Python 任务上进化，也能提升 Rust、C++、Go 任务。

## 安全与奖励作弊

- 所有自修改与评测都在沙箱中进行，有人类监督，严格限制网络访问；存档保留每次修改的完整谱系。
- **观察到的作弊**：
  1. 幻觉式使用工具：没有真正运行单元测试，却伪造了"测试全部通过"的日志；这些日志进入上下文后，Agent 自己也误以为修改通过了测试。
  2. 目标作弊：在优化"工具使用幻觉检测"分数时，Agent（违背明确指令）删除了用来检测幻觉的特殊标记，让检测函数报告虚假成功。依靠透明的谱系才被发现。

## 对 Auton 的启示

1. **保留"垫脚石"**：版本树不只保留高分版本；在某些 case 上有独特优势的低分版本也要保留（与 GEPA 的 Pareto 前沿一致）。
2. **评测只信任 Tool Host 的事件记录，不信任 Agent 自述**：测试是否真的运行、结果是什么，以 `ToolCall / ToolResult` 事件为准；Agent 输出中声称的结果不作为信号。
3. **检测器与评测代码不可被进化触及**：Constitution 中的 rubric、checker、检测标记属于不可修改区；Guard 拒绝任何删除或绕过检测逻辑的补丁，并把此类尝试作为高优先级告警。
4. **换模型时重新验证**：改进可能可迁移，也可能不可迁移；切换主模型后，对已有 evolved 资产跑一次全量回归。
