## 核心观点

Agent 评测需要清楚区分任务、重复试验、评分器、轨迹和环境中的最终结果。

## 机制与证据

- 一个任务可包含多个 grader；通过重复 trial 观察随机性。
- 结合代码、模型和人工评分，模型评分需要人工校准。
- 能力评测探索当前边界，回归评测保护已有能力；成熟能力用例可以转入回归集。
- 最终结果应检查环境状态，不能仅凭 Agent 的完成声明。

## 对 Auton 的启示（待验证）

- §6.4：Eval Store 分别记录数据划分（train/val/test）与用途（能力/回归），两者相互独立。
- §6.1、§6.2：为 task、trial、grader 和 outcome 建立独立标识与结果记录。
- §7.5：按任务需要检查最终状态，避免把某条固定执行路径当作唯一正确答案。

## 局限

工程经验报告不是受控算法对比；不能直接用其中案例设定 Auton 的统一通过阈值。
