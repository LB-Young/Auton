## 核心观点

SFTTrainer 支持对话与 prompt-completion 数据，工具调用样本需要消息和可用工具定义。assistant-only loss 与模板支持有关，不能只设置一个开关就假定全部样本正确遮罩。

## 我的理解

训练数据不是聊天日志的另存为。日志描述发生了什么，SFT 目标描述模型应该学什么；两者之间需要正确目标、当时输入重建、来源与 loss mask 检查。

## 对 Auton 的启示

- 训练正确 assistant 答复和动作，不默认对用户、工具输出或错误中间动作计损失。
- 样本保留当时工具 schema 与调用/响应关联，避免用错版本协议监督。
- 评分结果、事后纠正与未来观测留在标签/证据层，不回填到过去输入。
- 同源任务、教师修复和增强样本先锁定 split，再生成训练目标。
- 真实数据不进公开仓库；导出训练 JSONL 与谱系 manifest 分开。

## 局限与验证

训练库支持某种格式不代表目标小模型能学会该能力。先抽样检查 tokenization、mask 和截断边界，再验证实际部署的工具轨迹和业务结果，不能只看训练 loss。
