## 核心观点

不断批准命令可能带来疲劳。文章用文件系统与网络隔离共同限定执行范围，使边界内操作更自主，同时降低越界影响。

## 关键机制与做法

- 沙箱约束需要覆盖执行的子进程。
- 仅限制文件或仅限制网络都不足以形成完整边界。

## 我的理解

这里可借鉴的是提前划清能力范围，而不是无条件扩大自动批准。工作目录、容器名称和提示词都不能代替操作系统实际执行的隔离。

## 对 Auton 的启示

- 把可读写路径、出站服务、凭据及进程能力放进可审计策略。
- 按真实副作用申请批准，边界内可逆操作尽量不反复打断用户。

## 局限与适用前提

隔离强度随操作系统、配置和工具实现改变；不能将某种沙箱的内部效果数字当作 Auton 的保证。

## 建议验证（尚未执行）

测试符号链接、子进程和网络重定向，同时验证任务内正常操作仍可完成。
