## 核心观点

代码模式让模型调用类型化 API 组合工具，而不把每一步中间结果都搬回模型。文中使用隔离执行和受控 bindings 连接服务。

## 关键机制与做法

- 生成代码在受限环境执行，必要结果通过输出返回。
- 限制一般出网，把服务访问收敛到指定能力入口。

## 我的理解

我理解核心是把确定性处理留在执行环境，而不是把安全责任交给生成脚本。一次脚本可能包含多次外部写，审计粒度仍应是业务操作。

## 对 Auton 的启示

- 代码 API 逐项经过授权、预算和 operation ledger。
- 脚本异常时保留已完成与未知项目，不按整体退出码重跑全部动作。

## 局限与适用前提

特定平台的 isolate 与 bindings 不能直接等同于本地子进程或容器；成本优势也需要自身任务验证。

## 建议验证（尚未执行）

对比逐工具与代码组合的读取，再在第 N 次写后崩溃，检查执行明细与恢复无盲重复。
