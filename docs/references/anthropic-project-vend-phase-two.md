## 核心观点

后续同时改进模型、工具与说明，加入 CRM、成本信息和 CEO Agent，业务表现改善，但仍存在受对抗性交互影响的问题，阶段也不是严格单变量对照。

## 关键机制与做法

- 业务工具让必要事实更可见。
- 多 Agent 管理增加目标压力与交流，付款仍保留人工边界。

## 我的理解

我理解不能把改善简单归因于增加老板角色。第二个模型也可能接受同一错误前提；关键权限不能依赖两个模型在聊天里达成同意。

## 对 Auton 的启示

- 做动作时展示成本、数量、预算和约束。
- 重要例外由确定性规则与绑定动作的批准控制，审查 Agent 的意见作为证据而非授权。

## 局限与适用前提

模型、工具和流程共同变化，不能据此证明多 Agent 因果收益；业务改善也不代表鲁棒性完成。

## 建议验证（尚未执行）

固定模型与工具后，比较单 Agent、双 Agent、代码门禁和组合，对抗输入下分别计违规与成本。
