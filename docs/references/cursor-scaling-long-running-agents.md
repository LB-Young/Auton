## 核心观点

平级 Agent 依赖共享文件自协调时，出现锁争用和缺少端到端责任的问题；团队改用分开的 planner 与 worker 角色探索大项目。

## 关键机制与做法

- 规划与执行分工，让 worker 聚焦边界较清楚的任务。
- 作者也强调删去不产生收益的协调复杂度。

## 我的理解

我理解扩展瓶颈通常不是“还缺一个角色”，而是任务是否能独立推进、最终责任是否清楚。锁保证某个修改互斥，不会自动保证有人处理最难的全局问题。

## 对 Auton 的启示

- 任务领取交给确定性调度器，以版本与租约控制提交。
- 同时测 worker 输出和最终可交付吞吐，集成队列增长时不继续盲目扩容。

## 局限与适用前提

研究项目的规模、算力和可接受错误率与个人助手不同，提交量不能替代实际质量。

## 建议验证（尚未执行）

对同一任务逐步增加 worker，记录冲突、等待、返工和最终验收通过量。
