## 核心观点

研究中，独立测试失败容易分工；构建内核时多 Agent 围绕同一 bug 修改并互相覆盖。团队借助 GCC 对照把失败分解到文件子集，再处理组合故障。

## 关键机制与做法

- 测试反馈、进度文档和快速子集帮助长期推进。
- 新功能破坏旧行为需要持续回归约束。

## 我的理解

我认为并发收益首先取决于诊断粒度。只有一个全局失败信号时，增加 worker 可能增加冲突；应先缩减和定位，再分配可独立验收的工作。

## 对 Auton 的启示

- 共享瓶颈先交诊断任务，定位后再委派修复。
- 整合版本跑完整验收，快速抽样只辅助探索，不作发布依据。

## 局限与适用前提

这是能力边界原型，不是生产可靠性证明；简单锁协议、无限循环和产物规模不能直接作为 Auton 默认方案。

## 建议验证（尚未执行）

比较独立缺陷、共同阻塞与组合缺陷三组项目在不同 worker 数下的有效吞吐和总成本。
