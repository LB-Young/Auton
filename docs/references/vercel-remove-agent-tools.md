## 核心观点

内部查询 Agent 原先依赖多种专用工具与精细编排，维护脆弱。改用沙箱读取清晰的语义层文件后，在仅 5 个代表查询的对比中改善。

## 关键机制与做法

- 文件中已有业务维度、计算与关联说明。
- 模型使用熟悉的检索方式探索，而非走多层固定包装。

## 我的理解

我理解收益可能同时来自更好的信息暴露和减少框架限制，不能简化为“工具越少越好”。删除导航包装也不意味着删除数据库权限与验证。

## 对 Auton 的启示

- 将导航辅助、业务动作、确定性控制分开评估。
- 新增工具记录解决的真实失败和退役标准，保留低复杂度基线。

## 局限与适用前提

样本很小，且依赖结构良好的语义层；不能把短期满分当长期可靠率。

## 建议验证（尚未执行）

对清晰与混乱 schema 分组比较专用、文件和混合方案，同时检查正确率与维护负担。
