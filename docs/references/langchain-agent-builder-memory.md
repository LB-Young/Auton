## 核心观点

Agent Builder 用文件形态呈现指令、技能和知识，底层可由数据库承载。团队遇到记得太多或太少、放错位置、格式不合适等实际问题。

## 关键机制与做法

- 让模型使用熟悉的文件接口，配合存储与格式验证。
- 特定重复任务比广泛通用任务更容易复用历史经验。

## 我的理解

我理解记忆的难点是治理和适用性，而不是选择向量库还是文件。模型会写文件不代表每次写入都应该立即影响后续任务。

## 对 Auton 的启示

- 分开临时 learning 和正式资产；给条目记录目的、作用域、来源和有效时间。
- 写入做结构校验与并发版本检查，允许用户审阅和撤回。

## 局限与适用前提

产品面向重复工作流，其热路径直接编辑策略不能不加调整地用于通用个人 Agent。

## 建议验证（尚未执行）

输入一次性要求、明确长期偏好和项目限定事实，检查记忆位置与后续行为是否符合范围。
