# 对话工作区

默认网页现在是对话入口。使用 `make server` 后打开 `http://127.0.0.1:5173`；只需在 `.env` 配置 `DEEPSEEK_API_KEY`，不需要在网页创建项目、工作区或选择验收类型。升级包含新后端接口，需要在原服务终端按 Ctrl+C，再运行 `make server`。

## 日常使用

- 左侧是历史对话，可搜索、新建或切换。标题使用首条消息，内容由后端持久保存；刷新会按 URL 中的 conversation ID 恢复。新建不会停止另一个对话中正在执行的任务。
- 中间按轮展示用户消息和助手回复。Enter 发送、Shift + Enter 换行；中文输入法选字不会触发发送。回答结束后直接追问，不必创建新的独立任务。
- 输入框旁只有执行模型下拉框，列出后端已注册的远程 API 和本地模型。本地选项显示模型版本或 adapter revision。新部署/发布的版本在后端注册后，刷新页面即可选择；下拉框不下载、训练或发布模型。
- 右上角按钮展开或收起工作面板，默认收起。需要批准操作、出现阻塞或暂停时自动展开，显示进度、操作预览、文件和运行详情。文件可预览和下载。手机端通过左上角打开历史导航，工作面板按覆盖层显示。
- 正在执行时可继续写草稿，发送按钮变成停止按钮。一轮结束后才能发送下一轮；阻塞或暂停时先在面板恢复、核对未知操作结果或停止。切换对话保留本页未发送的草稿；未发送草稿不保证浏览器刷新后保留。

## 会话与执行

每个对话自动创建独立的空项目和受控工作区，使用当前身份拥有的资源，不关联已有其他项目的资料。每轮继续调用原有 Agent Runtime：决策建议、上下文预算、模型网关、受控工具、审批、事件日志、执行轨迹及反馈接口均保留。没有额外的 Demo 兜底。

后端从已保存的轮次构建下一轮的用户/助手历史，客户端不能在会话接口伪造此前消息。当前策略保留消息和最终回复；先前轮次的工具原文不会直接拼入聊天历史，工作区文件可由后续受控工具按需读取。上下文引擎仍可能因 token 预算压缩较早的消息。聊天记录不等于无限记忆。

普通对话使用 `response-present-v1` 检查是否产生非空回复，不要求资料引用，也不等于证明答案正确或任务质量合格。原来的调研引用检查、精确文件 SHA256 检查继续用于相应任务。文件写入仍需要对具体操作逐项批准，模型不能通过自然语言跳过审批；自动创建工作区也不会开放任意宿主目录或任意 shell。

每轮使用持久请求标识和预期轮次做幂等及并发检查；HTTP 响应丢失后原内容重试会返回同一轮，而不是重新计费执行。并发标签页若基于过期轮次发送，会明确冲突，需重新加载。会话之间及历史查询均按身份隔离。

当前边界：每条用户消息最多 4000 字符，每个对话最多 40 轮；达到上限后新建对话。历史列表最多读取 1000 个会话，超过时返回显式错误。运行预算、模型上下文和输出限制仍由后端配置，不因换成聊天界面而放宽。API key、模型可用性、预算不足、工具失败仍会显式提示。

## 远程与本地模型

选择远程模型后，发送按钮下会说明接收方。点击发送表示允许将本次消息、本对话历史及本会话中工具读取的文件内容用于该远程模型；服务端要求本轮显式 `allow_remote=true`。选择本地模型时使用 local-only 域。后端的 provider 白名单、敏感信息检测和凭据保护继续生效，选择模型不授予其他项目资料的访问权限。

`make server` 预设使用 DeepSeek；本地执行模型需要在最终部署环境配置并注册。流程见 [本地运行时与发布](local-runtime-and-release.md) 和 [模型配置](configuration.md)。未配置、缺少凭据或不可用的模型不会伪装成已成功运行。

## 决策模型与执行模型学习

两个学习链路继续保留在后端。对话轮次仍产出真实 AgentRun、决策记录和 trajectory，继续供复核、数据集、训练、评估、发布等已有模块使用。切换前端界面不会清理历史数据，也不会自动训练或自动上线本地版本。

数据使用授权、数据切分、失败样本复核、独立测试集、影子评估及上线审批仍走后端原有流程。非空回复验收不能替代质量复核。普通对话的确定性评测返回质量 unknown，不会因缺少资料引用而被当作失败，也不会直接成为优质样本。执行器 SFT 目前仍限定独立验证的文件操作，新增普通聊天先保留为候选轨迹，不会自动转换成 SFT 数据；新的对话项目不会自动继承旧项目的数据使用授权。`training`、`decision_training` 和 `operations` 的默认关闭状态不变。参见 [全部功能](usage.md)、[决策学习](jev-decision-learning.md)、[训练与发布配置](configuration.md)。

旧工作台不再作为普通入口。开发验收需要时可使用 `?legacy=1&view=agent` 或对应模块 view；这些兼容页面和原有 API 保留，正常界面不显示模块配置导航。旧的 `?view=agent` 或 `?view=chat` 书签也会进入新的对话工作区。

## API

| 路径 | 用途 | 核心参数 |
| --- | --- | --- |
| `GET /api/v1/conversations` | 当前身份的历史会话 | 无 |
| `POST /api/v1/conversations` | 幂等创建会话及隔离资源 | `request_id`, `title` |
| `GET /api/v1/conversations/{id}` | 会话和持久轮次 | 会话 ID |
| `POST /api/v1/conversations/{id}/turns` | 发送下一轮 | `request_id`, `expected_turns`, `text`, `model_id`, `allow_remote` |

模型列表复用 `GET /api/v1/models`；运行状态、流式生成快照、审批/停止/恢复及产物复用原 Agent 与工具接口。浏览器按快照轮询展示生成中的临时文字，最终回复以持久事件为准。完整参数见 [API 字段参考](reference/api-schemas.md)。

实现边界：`auton.conversation` 提供 contracts、ports、service 和 factory；前端 `features/conversation` 的 controller 通过 transport ports 访问后端。会话模块不直接调用模型 provider、训练实现或服务端接口；主装配通过工厂连接既有 Agent、模型目录、工具及事件存储。
